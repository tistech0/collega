# Beta TestFlight : APNs production avec repli sandbox, bundle com.matthislesur.collega, pages publiques /legal

> Un build TestFlight donne un jeton APNs de production, un build installé depuis Xcode un jeton sandbox, et l'app ne p…

Un build TestFlight donne un jeton APNs de production, un build installé depuis Xcode un jeton sandbox, et l'app ne peut pas savoir lequel elle a. APNsNotificationService tient deux clients aioapns : l'environnement configuré (APNS_USE_SANDBOX, défaut False) puis l'autre si APNs répond BadDeviceToken ; aucune colonne en base. Bundle ID de l'app et défaut APNs : com.matthislesur.collega (renommé le 2026-09-26 avant la création de l'app dans App Store Connect ; l'ancien com.lesurmatthis.collegaApp n'existe plus). En prod, APNS_* sont dans le .env du NAS et la clé .p8 est montée en lecture seule. Les pages publiques exigées par App Store Connect sont servies par l'API sur /legal/privacy, /legal/terms, /legal/support (sans auth, markdown-it-py sans HTML brut) ; les Markdown sont copiés dans collega_backend/app/static/legal/ (l'image Docker ne voit pas collega_app/) et un test impose l'égalité avec collega_app/assets/legal/. Cloudflare Access : application « collega-legal » en Bypass sur collegatest.matthislesur.com/legal (vérifié : /legal/* 200 et /health 302 depuis le chemin public).
Evidence: Prod 5e82ccd : logs api/worker « Notification service initialized (type=APNsNotificationService, sandbox=False) » ; curl --resolve 104.21.37.178 : /legal/* 200, /health 302

## Verification

Prod 5e82ccd : logs api/worker « Notification service initialized (type=APNsNotificationService, sandbox=False) » ; curl --resolve 104.21.37.178 : /legal/* 200, /health 302

# Console admin (`collega_backend/app/static/admin/js`) — convention à suivre pour tout écra

> Console admin collega backend/app/static/admin/js — convention à suivre pour tout écran avec polling setInterval/setT…

Console admin (`collega_backend/app/static/admin/js`) — convention à suivre pour tout écran avec polling (setInterval/setTimeout) : le routeur maison (`main.js` `render()`) n'annule pas proprement un écran en cours de premier chargement. Si une navigation (hashchange) survient pendant le `await view.render(...)` d'un écran précédent, l'ancien `render()` se termine après le nouveau et écrasait `cleanup` avec le sien (obsolète) — l'intervalle/timeout de l'ancien écran continuait de tourner indéfiniment et le cleanup du nouvel écran devenait inatteignable. Corrigé (fix round 1 de task 9, commit a843bbb) avec un compteur `renderToken` : incrémenté en tête de `render()`, comparé après le `await view.render(...)` — si un render plus récent a démarré entretemps, le cleanup obtenu est appelé immédiatement et jamais stocké dans la variable `cleanup` module-level. `renderToken` est aussi incrémenté dans `logout()` et sur l'event `admin:logout` pour la même raison.

Convention pour chaque vue qui poll (`imports.js`, `import.js`, et toute future vue avec rafraîchissement périodique) : déclarer `let stopped = false;` **avant** le premier `await` de `render()` (pas après), le vérifier après chaque `await` dans `load()`, et ne réarmer le timer que si `!stopped` ; le cleanup retourné fait `stopped = true`. Préférer une chaîne `setTimeout` auto-programmée (le prochain appel posé dans un `finally` après le précédent) à un `setInterval` brut, pour ne jamais empiler des requêtes si une réponse est lente (ex. Cloudflare) — sinon une réponse plus ancienne peut écraser une réponse plus récente dans l'UI.

Vérifié par Playwright : compter les requêtes réseau pendant ~12 s après avoir quitté un écran (0 attendu), y compris dans le scénario où la navigation a lieu PENDANT le premier chargement (route interceptée et ralentie pour élargir la fenêtre de course) — sans le fix du render token, ce dernier scénario laissait échapper des requêtes.
Evidence: Playwright : 0 requête /v1/admin/queue et /v1/admin/jobs/ en 12s après navigation, y compris navigation déclenchée 100ms après ouverture de l'écran avec /jobs/** ralenti de 800ms côté route intercept.
Verified by: node verify_fix_round1.js (script Playwright de session)

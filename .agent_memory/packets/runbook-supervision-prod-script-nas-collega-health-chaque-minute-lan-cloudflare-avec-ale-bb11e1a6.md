# Supervision prod : script NAS collega-health chaque minute (LAN + Cloudflare) avec alerte Telegram immédiate

> Depuis le 2026 09 23, le User Script Unraid collega health source versionnée : collega backend/ops/nas/collega health…

Depuis le 2026-09-23, le User Script Unraid `collega-health` (source versionnée : collega_backend/ops/nas/collega-health.sh, installée dans /boot/config/plugins/user.scripts/scripts/collega-health/script) tourne chaque minute (schedule.json « * * * * * » + ligne dans customSchedule.cron, puis /usr/local/sbin/update_cron). Il sonde GET /health (qui vérifie Postgres et Redis) par deux chemins : LAN via NPM (`--resolve collegatest.matthislesur.com:443:192.168.1.10`) et public via Cloudflare (IP résolue par `dig @1.1.1.1`, service token lu dans /boot/config/secrets/collega_cf_access et passé à curl par stdin `-K -`, jamais en argument). Un échec est re-testé 10 s plus tard ; s'il persiste, alerte immédiate « Collega : API en panne » via /usr/local/emhttp/webGui/scripts/notify (niveau alert → Telegram), puis UN message « Collega : API rétablie » (niveau normal) au retour ; état par chemin dans /tmp/collega-health/{lan,public} (RAM). Choix de l'utilisateur : pas de service externe (healthchecks.io refusé) et rien dans le récap Telegram de 8 h ; limite assumée : si le NAS entier meurt, aucune alerte. Journal : /tmp/user.scripts/tmpScripts/collega-health/log.txt.
Evidence: Exécution manuelle puis par cron 18:42 : « lan 200 ok », « public 200 ok » ; ligne cron présente dans /etc/cron.d/root.

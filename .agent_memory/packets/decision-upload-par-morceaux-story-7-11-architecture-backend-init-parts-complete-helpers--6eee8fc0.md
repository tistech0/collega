# Upload par morceaux (story 7.11) : architecture backend init/parts/complete + helpers d'import partagés

> Cloudflare rejette tout body 100 MB 413 HTML sans detail.code . Au delà de 90 MB l'app passe par POST /v1/colleges/{r…

Cloudflare rejette tout body > 100 MB (413 HTML sans detail.code). Au-delà de 90 MB l'app passe par POST /v1/colleges/{ref_id}/import/init (gardes en lecture seule via _assert_import_allowed, quota NON consommé, 413 FILE_TOO_LARGE > 500 MB) → PUT /v1/colleges/import/{upload_id}/parts/{n} (body binaire brut, 25 MB fixés par le serveur, idempotent, authentifié par l'upload_id seul) → POST /v1/colleges/import/{upload_id}/complete (vérifie user_id, 409 UPLOAD_INCOMPLETE + missing, magic bytes sur part_0, claim atomique par DEL Redis → perdant 409 JOB_IN_PROGRESS, assemble puis _start_import_from_file qui renomme en {college.id}_{job_id}.pdf — convention exigée par le glob de purge admin — et enqueue l'OCR ; 503 QUEUE_UNAVAILABLE restaure l'état Redis et garde les morceaux). État : ChunkedUploadStore (app/services/upload/chunked_upload.py) = hash upload:{id} + set upload:{id}:parts TTL 24 h dans le Redis ARQ (redis.asyncio, satisfait le Protocol UploadRedis) + morceaux sur {pdf_storage_path}/uploads/{id}/part_{n}. Cron worker cleanup_stale_uploads (xx:30) purge les dossiers sans clé ou > 24 h. Le refacto de POST /import a été fait en helpers (_get_or_create_college, _assert_no_active_job, _apply_reimport_quota, _create_job_and_enqueue) pour conserver EXACTEMENT la séquence de db.execute que les tests existants chaînent en side_effect — c'est pourquoi le plan (qui appelait _assert_import_allowed puis _start_import_from_file dans /import) n'a pas été suivi à la lettre : 0 test existant modifié.

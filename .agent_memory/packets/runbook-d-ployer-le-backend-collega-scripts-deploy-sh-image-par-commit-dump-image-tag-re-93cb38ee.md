# Déployer le backend Collega : scripts/deploy.sh (image par commit, dump, IMAGE_TAG, retour arrière)

> Depuis le chantier 3 2026 09 24 , le déploiement se fait UNIQUEMENT par collega backend/scripts/deploy.sh force <sha …

Depuis le chantier 3 (2026-09-24), le déploiement se fait UNIQUEMENT par `collega_backend/scripts/deploy.sh [--force] [<sha>]` depuis le Mac (OrbStack lancé, commit poussé). Le script construit `tistech0/collega-backend:<sha>` (plus de tag latest) depuis un git worktree du commit, vérifie que app/main.py de l'image = celui du commit, pousse ; sur le NAS (`ssh nas`) il attend qu'aucun import ne tourne (arq:in-progress, arq:queue, jobs actifs ; 30 min max), fait un dump pg_dumpall dans /mnt/user/appdata/collega/backups/collega_pre_<sha>_<date>.sql.gz, valide puis installe le docker-compose.prod.yml DU COMMIT (ancien en .bak), change seulement la ligne IMAGE_TAG du .env (sauvegarde .env.bak-<date>), compose pull/up, attend api+worker healthy et affiche migrate + /health. Retour arrière = `deploy.sh <sha précédent>` (testé : 4a9f966 puis 7a2f3ef) + restauration du dump si le schéma a changé. `--force` est nécessaire tant que `gh` local est connecté au compte CrazyGrower qui ne voit pas le dépôt privé tistech0/collega (la vérification CI renvoie « inaccessible ») ; la CI se rejoue alors en local : backend avec `act push -j backend -P ubuntu-latest=catthehacker/ubuntu:act-latest --container-architecture linux/arm64 --pull=false` (arrêter d'abord docker-compose.test.yml : ports 55432/56379), app dans `ghcr.io/cirruslabs/flutter:3.27.1` (flutter-action ne gère pas arm64). Prod : image non root uid 1000 (dossier /mnt/user/appdata/collega/pdfs chown 1000:1000), Redis avec --requirepass ; REDIS_PASSWORD ajouté au .env du NAS, REDIS_URL surchargé dans le compose par `environment:`, REDISCLI_AUTH posé dans le conteneur redis donc `docker exec collega-redis-1 redis-cli …` marche sans mot de passe en argument.
Evidence: Déploiements réels 2026-09-24 : 7a2f3ef, retour arrière 4a9f966 puis 7a2f3ef, api/worker healthy, /health ok, redis-cli sans auth → NOAUTH, dump collega_pre_7a2f3ef_20260924-200428.sql.gz.
Verified by: deploy.sh exécuté sur le NAS + docker inspect

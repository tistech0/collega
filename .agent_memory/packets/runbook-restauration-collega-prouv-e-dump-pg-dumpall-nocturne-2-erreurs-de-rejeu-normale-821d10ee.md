# Restauration Collega prouvée : dump pg_dumpall nocturne, 2 erreurs de rejeu normales, mot de passe de prod restauré

> Le dump nocturne /mnt/user/nas backup/dumps/collega db 1.sql.gz backup dumps : pg dumpall clean if exists , un seul f…

Le dump nocturne /mnt/user/nas-backup/dumps/collega-db-1.sql.gz (backup-dumps : `pg_dumpall --clean --if-exists`, un seul fichier écrasé chaque nuit ; historique dans kopia /dumps et R2) se restaure intégralement. Procédure et explications dans collega_backend/docs/restore.md. Points non évidents : (1) exactement 2 erreurs au rejeu (`current user cannot be dropped`, `role "postgres" already exists`) = les « 2 erreurs de rejeu » du journal backup-verify, sans conséquence ; (2) le dump restaure le mot de passe de prod du rôle postgres → un conteneur de test doit être en POSTGRES_HOST_AUTH_METHOD=trust sur un réseau `--internal` ; (3) items.ocr_text est vide pour les imports de plus de 24 h (purge cleanup_ocr_text), ce qui fait fondre le dump (416 Ko → 64 Ko le 23/09) sans perte ; (4) la version Alembic du dump peut être en retard (015 alors que la prod était en 017 après un déploiement en journée) : `alembic upgrade head` la rattrape. PDF et .env sont dans kopia sous /source/collega/pdfs et /source/compose-stacks/collega/.env (conteneur `kopia`, appdata monté sur /source) ; restauration kopia non testée en réel.
Evidence: 2026-09-23 sur le NAS, conteneur postgres:16-alpine jetable (réseau interne, trust) : rejeu avec 2 erreurs de rôle, puis image 2083f55 `alembic upgrade head` (015→016→017 OK) et lecture ORM : 4 users, 2 colleges, 341 flash_cards ; 44 items dont 0 avec ocr_text ; conteneur et réseau supprimés.
Verified by: restauration réelle dans un Postgres jetable sur le NAS, 2026-09-23

## Verification

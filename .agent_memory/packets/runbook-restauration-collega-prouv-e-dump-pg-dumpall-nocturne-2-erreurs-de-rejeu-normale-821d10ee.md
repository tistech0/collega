# Restauration Collega prouvée : dump pg_dumpall nocturne, 2 erreurs de rejeu normales, contenu par empreinte inclus

> Le dump nocturne /mnt/user/nas backup/dumps/collega db 1.sql.gz backup dumps : pg dumpall clean if exists , un fichie…

Le dump nocturne /mnt/user/nas-backup/dumps/collega-db-1.sql.gz (backup-dumps : `pg_dumpall --clean --if-exists`, un fichier écrasé chaque nuit ; historique dans kopia /dumps et R2) se restaure intégralement. Procédure : collega_backend/docs/restore.md. Points non évidents : (1) exactement 2 erreurs au rejeu (`current user cannot be dropped`, `role "postgres" already exists`) = les « 2 erreurs de rejeu » de backup-verify, sans conséquence ; (2) le dump restaure le mot de passe de prod du rôle postgres → un conteneur de test doit être en POSTGRES_HOST_AUTH_METHOD=trust sur un réseau `--internal` ; (3) depuis la migration 018 (chantier 1), le texte OCR est conservé (ocr_pages, item_texts, item_generations, dans le même dump) : le dump grossit avec les collèges — les anciens dumps fondaient parce que items.ocr_text était purgé à 24 h ; (4) la version Alembic du dump peut être en retard sur le code (migration déployée en journée) : `alembic upgrade head` la rattrape. PDF et .env dans kopia sous /source/collega/pdfs et /source/compose-stacks/collega/.env (conteneur `kopia`) ; restauration kopia non testée en réel.

# PDF local (partie B) : version = id du dernier job publié, copie datée par l'app, pdfrx 1.0.103

> Le PDF importé est relu dans l'app. Serveur : services/imports.current pdfs DISTINCT ON college id, dernier job gener…

Le PDF importé est relu dans l'app. Serveur : services/imports.current_pdfs (DISTINCT ON college_id, dernier job generation_complete dont le fichier existe) alimente pdf_version (id du job, pas pdf_hash qui est nullable) et pdf_size dans GET /v1/colleges, et la route GET /v1/colleges/{id}/pdf (FileResponse, Range/206, 404 COLLEGE_NOT_FOUND pour un autre compte, 404 PDF_NOT_FOUND). Items : start_page/end_page base 0 en base, affichés et navigués en base 1. App : features/pdf/ ; LocalPdfStore garde <collegeId>_<jobId>.pdf dans Application Support/pdfs, exclu d'iCloud par le canal natif collega/backup (AppDelegate.swift). Piège vérifié : File.copy conserve la date de modification du fichier source et la précision n'est que d'1 s, donc l'ordre des versions (réimport non publié gardé, versions plus anciennes supprimées) repose sur _stamp qui date chaque nouvelle copie strictement après les autres. Copie faite dans _afterUploadAccepted (source intacte après l'envoi par morceaux), purge dans _loadUserColleges (deleteExcept) et au changement de compte (LocalDataOwner.clearPdfs). Téléchargement via background_downloader avec Task.split (chemin relatif : le conteneur iOS change entre lancements). Sans pdf_version (backend ancien), la ligne dit « indisponible pour l'instant » et le lecteur n'offre aucun bouton. pdfrx épinglé à 1.0.103 tant que Flutter reste en 3.27 (1.1.x exige 3.29). Drift : schéma 10 (pages des items, pdfVersion/pdfSize dans user_colleges). En widget test, les E/S fichier réelles ne se terminent pas sous testWidgets : utiliser un store en mémoire.
Evidence: backend 962 tests, app : tous les dossiers verts le 2026-09-26 ; test « réimport d'un PDF à date ancienne » ; mesure dart : copySync garde 2020-01-01, résolution 1 s

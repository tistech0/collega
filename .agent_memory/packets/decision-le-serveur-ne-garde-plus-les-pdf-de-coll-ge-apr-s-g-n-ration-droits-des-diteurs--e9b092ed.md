# Le serveur ne garde plus les PDF de collège après génération (droits des éditeurs) ; copie seulement sur le téléphone, rattachement par SHA-256

> Décision du 2026 10 02 raison juridique : ne pas stocker d'exemplaires d'œuvres protégées, les collèges sont des livr…

Décision du 2026-10-02 (raison juridique : ne pas stocker d'exemplaires d'œuvres protégées, les collèges sont des livres payants). generation_worker supprime tous les PDF du collège ({college_id}_*.pdf) juste après publish_job. purge.active_pdf_names ne garde plus que les imports actifs (pending/processing/ocr_complete) ; la purge de nuit (maintenance_worker.purge_content) appelle d'abord backfill_pdf_hashes pour remplir GenerationJob.pdf_hash des imports publiés anciens tant que le fichier existe. imports.current_pdfs renvoie le dernier job generation_complete même sans fichier : size=None, sha256=pdf_hash. Le catalogue garde donc pdf_version (sinon l'app, via keepOnlyServed, effacerait les copies locales) avec pdf_size=null ; GET /colleges/{id}/pdf répond 404 PDF_NOT_FOUND quand le fichier n'est plus là. Nouvelle route GET /v1/colleges/{id}/pdf/fingerprint -> {pdf_version, pdf_sha256}. Côté app : pdf_size null => PdfMissingView propose « Choisir mon PDF » (PdfAttachNotifier : file picker, SHA-256 dans un Isolate, comparaison avec l'empreinte serveur, keepCopy si identique ; empreinte serveur null => accepté). file_sha256 est maintenant dans app/services/imports.py. Le texte extrait reste en base (régénération). CGU §7 et confidentialité §4 décrivent ce fonctionnement : à garder cohérents.
Evidence: pytest backend 1032 passed ; flutter test test/features/pdf, colleges, core, legal, profile verts ; flutter analyze propre

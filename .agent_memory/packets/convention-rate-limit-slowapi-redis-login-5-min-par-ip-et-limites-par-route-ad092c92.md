# Rate limit slowapi + Redis : login 5/min par IP et limites par route

> Le rate limiting du backend collega utilise slowapi avec un stockage Redis. Le Limiter partagé est défini dans colleg…

Le rate limiting du backend collega utilise slowapi avec un stockage Redis. Le Limiter partagé est défini dans collega_backend/app/core/limiter.py (`Limiter(key_func=get_client_ip, storage_uri=settings.redis_url)`) et branché dans collega_backend/app/main.py (`app.state.limiter = limiter` + handler `RateLimitExceeded`). `POST /v1/auth/login` : `@limiter.limit("5/minute")` (auth.py), clé = IP client prise dans le 1er élément de X-Forwarded-For. Autres limites : delete account 3/min (auth.py), search 30/min par user_id (search.py), notifications 10/min (notifications.py), régénération de fiche 10/hour (flash_cards.py). Limites connues (audit 2026-09-23, chantier 2) : X-Forwarded-For falsifiable par le client, aucune limite sur l'auth admin/tester, /refresh ni /evaluate-semantic, et slowapi sans swallow_errors → Redis coupé = 500 sur les routes limitées ; en tests, les compteurs vivent dans le Redis local et font échouer des tests au 2e lancement (429 == 200).
Evidence: grep @limiter.limit dans app/api/v1 (auth 5/minute et 3/minute, search 30/minute key_func=_user_id_key, notifications 10/minute ×2, flash_cards 10/hour) ; main.py app.state.limiter ; audit sécurité et code du 2026-09-23 (_bmad-output/planning-artifacts/audit-back-infra-2026-09-23.md).

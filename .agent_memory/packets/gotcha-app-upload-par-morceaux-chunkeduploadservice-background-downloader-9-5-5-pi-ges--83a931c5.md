# App : upload par morceaux (ChunkedUploadService + background_downloader 9.5.5) — pièges rencontrés

> Côté Flutter, l'aiguillage se fait dans CollegeImportNotifier.startImport : size 500 MB → ImportError 'file too large…

Côté Flutter, l'aiguillage se fait dans CollegeImportNotifier.startImport : size > 500 MB → ImportError('file_too_large') sans réseau ; size > 90 MB (ChunkedUploadService.chunkThreshold) → chunkedUploadServiceProvider (FutureProvider, cacheDir = getTemporaryDirectory) ; sinon chemin mono-requête inchangé. ChunkedUploadService (lib/core/upload/) : init → ligne Drift pending_uploads (schéma v6) → PartSplitter écrit parts_{uploadId}/part_n dans le cache → PartTransport.enqueue → attend PartDone de tous → complete → supprime la ligne + les morceaux. Reprise : CollegesScreen appelle resumePendingUpload() au montage et à chaque onResume (status serveur → seuls les morceaux manquants et non déjà en file sont renvoyés). Pièges : (1) background_downloader 9.5.5 : allowPause est incompatible avec post:'binary' (assert du package) → ne pas le passer sur UploadTask ; avec BaseDirectory.root le package retire le '/' initial de directory ('tmp/parts_u1'). (2) AsyncNotifier.build() est async : dans les tests, appeler `await container.read(collegeImportProvider.future)` AVANT startImport/resumePendingUpload, sinon la résolution de build() écrase l'état ImportUploading(progress) pendant les await. (3) Tout écran qui monte CollegesScreen en test widget doit overrider databaseProvider (AppDatabase.forTesting(NativeDatabase.memory())), partTransportProvider (InMemoryPartTransport) et uploadCacheDirProvider, sinon appels natifs (path_provider / sqlite isolate → « Callbacks into the Dart VM are currently prohibited »). (4) reset() du notifier ne coupe plus un ImportUploading(progress != null) : l'écran d'import fait reset() dans initState et aurait masqué un upload en cours. (5) Les 5 exceptions d'import (SubscriptionRequired, JobInProgress, …) vivent désormais dans lib/core/upload/upload_models.dart et sont ré-exportées par college_import_repository.dart pour éviter une dépendance circulaire avec upload_api.dart (mapImportDioError, qui mappe aussi le 413 HTML Cloudflare sur FileTooLargeException).
Evidence: flutter test test/core test/features/colleges : 82 passed ; flutter analyze : 0 nouvelle issue. Échec initial du test de progression reproduit puis corrigé par l'await du build ; log ERROR:flutter « Callbacks into the Dart VM » reproduit dans colleges_screen_test avant l'override des providers.

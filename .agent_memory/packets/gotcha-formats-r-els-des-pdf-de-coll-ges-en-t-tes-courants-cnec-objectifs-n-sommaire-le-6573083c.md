# Formats réels des PDF de collèges : en-têtes courants CNEC, OBJECTIFS N°, sommaire, lettrines — pièges de ItemDetector

> Les PDF de collèges n'ont pas un format unique. CEP Pneumologie 2023 : page d'en tête « Item 75 \n Addiction au tabac…

Les PDF de collèges n'ont pas un format unique. CEP (Pneumologie 2023) : page d'en-tête « Item 75 \n Addiction au tabac. \n Rang Rubrique Intitulé », titre sur 1-2 lignes (continuation en minuscule), parfois en CAPITALES, parfois un seul mot (Pneumothorax), lettrine cassée possible (338 « Œ Q A / DEME DE UINCKE » → illisible, comblé par un libellé official). CNEC (Cancérologie 4e éd.) : « Item 290 » est un EN-TÊTE COURANT répété sur chaque page (avant la story 8.0, chaque page devenait un item → la dédup gardait UNE page par item ; les fiches CNEC générées avant 8.0 le sont sur une seule page) ; le titre est dans « OBJECTIFS: N° 304. Titre » (variantes « OBJECTIFS : », « N"o300. ») ; le sommaire p2-3 « Chapitre 18 : Titre ..... 307 \n Item 308 » était pris pour l'en-tête de l'item 306 ; « . Item 313 » (ponctuation OCR) n'était pas détecté ; « tem 30 » = en-tête tronqué des deux côtés (ne pas tolérer « tem »). items.ocr_text est purgé 24 h après génération (cleanup_ocr_text) : pour ré-extraire quoi que ce soit, relire le PDF sur le volume /tmp/collega_pdfs/{college_id}_{uuid}.pdf dans collega-worker-1 (python -m scripts.backfill_item_titles, -m obligatoire). Pour tester l'extraction sur la prod sans déployer : concaténer item_titles (partie pure) + item_detector dans un script et le piper dans `ssh nas 'docker exec -i collega-worker-1 python -'`.
Evidence: Essais sur les 2 PDF de prod (CEP ed9a1032, CNEC 4ab16fc4) : avant 290 p20 seul, après p12-27 ; 44/44 items titrés après rattrapage le 2026-09-22.
Verified by: SQL prod après migration 015 + script : CNEC 23/23, CEP 21/21 titrés

## Verification

# Backend après chantier 5 : routes par domaine, AppError, pool ARQ du lifespan, service d'import, réglages en base

> Depuis le chantier 5 déployé le 2026 09 24, image f961861, migration 019 : les routes vivent dans des paquets par dom…

Depuis le chantier 5 (déployé le 2026-09-24, image f961861, migration 019) : les routes vivent dans des paquets par domaine — app/api/v1/colleges/{catalog,imports,status,cards}.py et app/api/v1/admin/{colleges,jobs,users,usage,config}.py, routeur exposé par __init__.py. Les erreurs passent par AppError et ses fabriques (app/core/errors.py : not_found, conflict, unprocessable, unauthorized, forbidden) ; install_error_handlers donne le corps {"detail": {"code", "message", ...extra à plat}} pour AppError, 422 (VALIDATION_ERROR, sans les valeurs saisies), 429 (RATE_LIMITED + Retry-After) et 500 (INTERNAL_ERROR) — toute mini-app de test qui lève AppError doit appeler install_error_handlers. Le pool ARQ est créé une fois dans le lifespan (app.state.arq), injecté par la dépendance get_arq (503 QUEUE_UNAVAILABLE si Redis indisponible, reconnexion paresseuse) ou get_arq_optional (Stop admin) ; jamais de create_pool dans une route ; en test, le faux pool est injecté par dependency_overrides[get_arq]. La logique d'import commune (collège, verrou, quota, sauvegarde du PDF, job + mise en file) est dans app/services/imports.py. Les limites anti-spam sont en base (table app_settings, anti_spam_limits(db) une fois par requête, cache 30 s par processus, .env = défaut, PATCH /v1/admin/config) ; le worker ne les lit pas. Le testeur web (/tester, /v1/tester, TESTER_*) n'existe plus ; les avis viennent de flash_cards.user_feedback. Piège corrigé : ne jamais lire un attribut ORM après db.rollback() (objet expiré → MissingGreenlet) — construire l'erreur avant.
Evidence: 570 tests verts, revue finale + re-revue propres ; prod : /tester 404, console admin 200, config persistée après redémarrage de l'API.

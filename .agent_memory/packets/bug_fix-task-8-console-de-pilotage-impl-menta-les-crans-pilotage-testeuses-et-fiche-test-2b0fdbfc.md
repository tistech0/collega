# Task 8 (console de pilotage) implémenta les écrans Pilotage, Testeuses et fiche testeuse e

> Task 8 console de pilotage implémenta les écrans Pilotage, Testeuses et fiche testeuse en JS vanilla collega backend/…

Task 8 (console de pilotage) implémenta les écrans Pilotage, Testeuses et fiche testeuse en JS vanilla (collega_backend/app/static/admin/js/views/{pilotage,testeuses,testeuse}.js), verbatim le code du brief task-8-brief.md, sans aucune déviation de structure : tous les champs consommés (GET /v1/admin/pilot -> PilotData/TesterRow/WatchJob/WatchFeedback/RunningJob, GET /v1/admin/users/{id} -> UserDetailData, POST /v1/admin/users, PATCH .../beta, POST .../reset-password (champ temporary_password), POST .../reset-quota, GET /v1/admin/config) correspondaient déjà exactement aux schémas Pydantic réels. Un vrai bug visuel a été trouvé en vérification manuelle (Playwright, 390px) : dans row() (ui.js), un span .muted contenant un bullet suivi d'une valeur (ex. e-mail d'une testeuse) à l'intérieur de .row .left pouvait wrapper sur deux lignes (le bullet isolé) quand le flex item se compressait sous sa largeur naturelle, car seule .row .left .t avait overflow/ellipsis/nowrap, pas .muted. Corrigé en ajoutant la règle `.row .left .muted { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; min-width: 0; }` dans css/ui.css (juste après la règle .t). Un prénom XSS `<img src=x onerror=alert(1)>` s'affiche bien en texte brut partout (titre h1, tableau, avatar-initiales) grâce à textContent — aucune exécution.

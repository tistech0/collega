# Beta TestFlight : APNs production par défaut avec repli sandbox, pages publiques /legal

> Un build TestFlight donne un jeton APNs de production, un build installé depuis Xcode même release, signature de déve…

Un build TestFlight donne un jeton APNs de production, un build installé depuis Xcode (même --release, signature de développement) un jeton sandbox, et l'app ne peut pas savoir lequel elle a. APNsNotificationService tient donc deux clients aioapns : l'environnement configuré (APNS_USE_SANDBOX, défaut False) puis l'autre si APNs répond BadDeviceToken ; aucune colonne en base. Le bundle APNs par défaut est com.lesurmatthis.collegaApp (l'ancien défaut com.lesurmatthis.collega était faux). Les pages publiques exigées par App Store Connect sont servies par l'API en HTML sur /legal/privacy, /legal/terms, /legal/support (sans auth, markdown-it-py sans HTML brut) ; les Markdown sont copiés dans collega_backend/app/static/legal/ car l'image Docker ne voit pas collega_app/, et un test impose l'égalité octet pour octet avec collega_app/assets/legal/. Côté Cloudflare, /legal doit être en Bypass Access comme /v1/webhooks/revenuecat.
Evidence: tests/services/test_apns_fallback.py et tests/api/test_legal_pages.py verts ; suite backend 950 passed

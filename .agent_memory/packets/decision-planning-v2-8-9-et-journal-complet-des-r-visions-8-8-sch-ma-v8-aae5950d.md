# Planning v2 (8.9) et journal complet des révisions (8.8, schéma v8)

> Depuis 8.8/8.9 : 1 review log journalise TOUTES les révisions ; colonne daily schéma Drift v8, défaut true pour les a…

Depuis 8.8/8.9 : (1) `review_log` journalise TOUTES les révisions ; colonne `daily` (schéma Drift v8, défaut true pour les anciennes lignes) = verdict de la session du jour. Le bilan de fin et la reprise (`lastVerdicts`, `verdictCounts`) filtrent `daily = true` ; « refaire les erreurs » et les drills collège/item/recherche écrivent `daily = false` ; `weekCounts` (semaine de Progression) compte les fiches distinctes par jour. (2) Le planning n'est plus qu'une période + collèges + minutes/jour (`planning_configs`) ; `planning_sessions` ne sert qu'aux jours décalés (status `postponed`). `PlanningGenerator` supprimé : la session du jour vient du moteur 8.3. « Décaler aujourd'hui » prolonge la période d'un jour (transaction `PlanningRepository.postpone`), refusé si la session du jour est commencée/faite ou hors période ; Aujourd'hui affiche « Session décalée à demain ». Écran `/progress/planning` (ancien `/planning/config` redirigé). (3) `progressProvider` est un StreamProvider.autoDispose abonné à `tableUpdates` (flash_cards, review_log) avec regroupement 150 ms.

# College.status n'était jamais avancé à generation_complete (job seulement) → import "jamais fini", /items 409

> Depuis le premier commit, CardGenerator.generate for college collega backend/app/services/generation/card generator.p…

Depuis le premier commit, CardGenerator.generate_for_college (collega_backend/app/services/generation/card_generator.py) ne mettait à jour que GenerationJob.status = generation_complete, jamais College.status. Or /v1/colleges/{id}/status renvoie college.status, le stream SSE n'émet generation_complete que si college.status == generation_complete, et /items répond 409 tant que college.status != generation_complete. Conséquence observée en prod le 2026-09-20 : job generation_complete avec 160 fiches, collège bloqué en ocr_complete, app et admin montrent un collège vide / import qui ne se termine jamais. Fix : helper _mark_college_generation_complete (UPDATE atomique sa_update(College).values(status=CollegeStatus.generation_complete)) appelé sur les deux chemins (hash-sharing et génération Claude) juste avant record_job_event/commit. Gotcha de tests : les tests hash-sharing (test_card_generator.py, test_token_usage_capture.py) mockent db.execute avec une liste side_effect stricte — tout nouvel execute dans ce chemin exige d'ajouter un MagicMock() à ces listes, sinon StopAsyncIteration. Pour réparer un collège déjà bloqué en prod : UPDATE colleges SET status='generation_complete' WHERE id=… (à condition que son job soit generation_complete).
Evidence: psql prod : colleges.status=ocr_complete alors que generation_jobs.status=generation_complete card_count=160 ; git log -S'college.status' sur card_generator/generation_worker : jamais écrit. Tests : tests/services/test_card_generator.py::TestCollegeStatusFinalisation (2 tests) rouges puis verts ; suite complète 316 passed, 16 échecs préexistants (Redis local, /register 403, APNs).

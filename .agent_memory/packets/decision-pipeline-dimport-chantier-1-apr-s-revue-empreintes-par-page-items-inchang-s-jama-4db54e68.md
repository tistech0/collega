# Pipeline d'import (chantier 1, après revue) : empreintes par page, items inchangés jamais regénérés, bascule gardée, quota rendu en échec

> Pipeline d'import depuis le chantier 1 spec bmad output/planning artifacts/chantier 1 fiabilite imports spec.md . OCR…

Pipeline d'import depuis le chantier 1 (spec _bmad-output/planning-artifacts/chantier-1-fiabilite-imports-spec.md). OCR (ocr_worker.run_ocr) : pages stockées par empreinte (ocr_pages) + job_pages (reprise) ; items détectés → job_items + item_texts. Empreinte d'item = SHA-256 du texte normalisé de SES PAGES (fingerprint.item_hash(pages)) : espaces/lignes vides retirés, et une ligne réduite à un nombre retirée seulement parmi les 3 premières/dernières lignes d'une page (numéros de page imprimés) — un nombre seul dans le corps (dose) compte. Génération (pipeline.generate_job_items) : un item inchangé (même text_hash que l'item en service) qui a déjà des fiches est SAUTÉ (sinon les collèges remplis par backfill_content_store, sans génération d'origine, repayaient tout) ; sinon génération réutilisée pour (text_hash, GENERATION_VERSION) ou Claude, validée item par item ; un appel ne compte que s'il a consommé des tokens. Bascule (publish.publish_job, collège puis job FOR UPDATE, rejouable) : inchangé → fiches gardées, ou ajoutées s'il n'en avait aucune ; modifié → même item id, fiches remplacées, MAIS sans génération exploitable l'ancien contenu et l'ancienne empreinte sont gardés ; nouveau ; disparu ; garde-fou : un réimport qui ferait disparaître plus de la moitié des items (≥ 4 en service) lève ImportRejected → rien modifié, fail_job. Quota : rendu si réimport sans appel Claude (bascule) et rendu aussi quand un réimport échoue (fail_job : erreur, Stop, cron bloqué). Verrous : toujours collège puis job (fail_job et publish_job). Contenu partagé : les écritures d'import prennent pg_advisory_xact_lock_shared(CONTENT_LOCK_KEY), la purge l'exclusif. Reprise : erreur → fail_job ; CancelledError (redéploiement) → job laissé actif, ARQ le relance ; job déjà ocr_complete à la reprise de l'OCR → génération remise en file avec l'id ARQ fixe gen:<job_id>. Purge des PDF : délai de grâce de 24 h pour tout fichier. Résumé (summary_json.reimport) exposé seulement pour un réimport.
Evidence: 551 tests backend verts deux fois (dont remplissage → réimport 0 appel, item modifié sans génération, garde-fou, quota rendu en échec, purge qui attend le verrou) ; revue de code indépendante du 2026-09-23 (2 critiques, 2 hautes, 4 moyennes corrigées).

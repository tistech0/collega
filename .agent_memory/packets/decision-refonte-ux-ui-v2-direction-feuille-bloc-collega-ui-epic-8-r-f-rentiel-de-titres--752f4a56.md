# Refonte UX/UI v2 : direction « Feuille × Bloc », Collega UI, epic 8 (référentiel de titres auto-alimenté)

> Session de cadrage des 2026 09 21/22 branche feat/redesign ux ui, commits 445f759 puis 326d372 : la refonte UX/UI de …

Session de cadrage des 2026-09-21/22 (branche feat/redesign-ux-ui, commits 445f759 puis 326d372) : la refonte UX/UI de l'app Flutter est spécifiée dans `_bmad-output/planning-artifacts/ux-design-specification-v2.md` (remplace la spec d'avril) et découpée dans `epic-8-refonte-ux-ui.md` (16 stories). Décisions structurantes : (1) nom **Collega** partout, « AppMédecine » disparaît ; (2) navigation à 4 onglets **Aujourd'hui · Bibliothèque · Progression · Profil**, la recherche devient une sheet plein écran hors onglets ; (3) session du jour **unique et mixte** (à revoir de tous les collèges du planning d'abord, puis nouvelles par rang A→B→C), **marquée faite automatiquement à la dernière fiche** — le bouton « Session terminée ✓ » disparaît ; (4) drill plein écran sarcelle, la réponse **glisse par le bas** (pas de flip 3D de l'écran), 3 gestes : swipe gauche = à revoir, haut = bien, droite = maîtrisé, doublés par 3 boutons ; (5) **inscription retirée** (`/auth/register` supprimée du routeur), login seul + « Beta privée · accès sur invitation », comptes créés à la main ; (6) design system **maison « Collega UI »** dans `lib/core/ui/` : 14 composants (CgButton, CgTabBar, CgHeader, CgListRow/Group, CgSegmented, CgSheet, CgDrillCard, CgVerdictBar, CgRing, CgRankBar, CgBadge, CgField, CgState, CgSkeleton/CgToast) sur primitives Flutter + Cupertino pour le natif ; **shadcn_ui conservé pendant la migration puis retiré (story 8.15)**, aucun widget Material visible. Direction visuelle « Feuille × Bloc » (maquette `directions-v2/direction-d-fusion.html`) : mise en page listes-à-filets, palette pierre `#ECEAE3` / surface `#F7F6F2` / ink `#17201F` / accent sarcelle `#0E5E63` / accent-soft `#D5E6E4`, états mastered `#0E5E63`, good `#6FA8A2`, review `#D9822B` (texte courant `#9A5A16`), unseen `#D9D6CC`, danger `#B8352B` ; police **Instrument Sans** ; thème clair unique ; iPhone seul. **Story 8.0, bloquante** : tout item doit avoir un titre. Cause : `ItemDetector._extract_chapter` (collega_backend/app/services/ocr/item_detector.py:33) ne matche que « chapitre X » / « partie X », motif absent des en-têtes réels « Item 310 – Tumeurs du testicule », d'où `chapter_title` vide en prod (CNEC, CEP) et des listes « Item 310 » sans nom. **Solution retenue (révisée le 2026-09-22, remplace l'idée d'une liste officielle fournie au départ) : cascade avec un référentiel qui se construit tout seul** — extraction depuis la ligne d'en-tête, puis chaque titre valide (5–200 caractères, ≥ 2 mots, pas majoritairement numérique) alimente une table globale `item_titles` (numéro, libellé, source `extracted`/`official`, occurrences) ; un item sans titre exploitable est complété par correspondance de numéro, libellé le plus fréquent (à égalité, le plus ancien) ; sinon NULL + warning, complété au prochain import. Les items de l'ECN étant universels, ce qu'un collège a bien scanné sert aux autres. La migration Alembic peuple le référentiel depuis les titres déjà en base puis backfille les items vides, sans réimport ni appel Claude. Une liste officielle pourra être injectée plus tard dans la même table avec la source `official`, prioritaire.
Evidence: Audit de 19 captures iPhone (build main 6d0a0ee) + lecture du code des 8 écrans non capturés : 70 écarts documentés dans `ux-audit-2026-09-21.html` (20 bloquants, 37 gênants, 13 cosmétiques). 3 directions maquettées en HTML interactif et comparées sur l'iPhone par l'utilisateur écran par écran avant la fusion. Cause de la story 8.0 vérifiée dans le code : `chapter_title` nullable (collega_backend/app/models/item.py:34), rempli uniquement par `_CHAPTER_PATTERN` (item_detector.py:33), valeur `""` quand le motif ne matche pas (item_detector.py:250).

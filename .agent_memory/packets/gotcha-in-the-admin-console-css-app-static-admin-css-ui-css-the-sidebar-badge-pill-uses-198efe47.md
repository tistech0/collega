# In the admin console CSS (app/static/admin/css/ui.css), the sidebar badge pill uses `<span

> In the admin console CSS app/static/admin/css/ui.css , the sidebar badge pill uses <span class="pill" hidden data bad…

In the admin console CSS (app/static/admin/css/ui.css), the sidebar badge pill uses `<span class="pill" hidden data-badge="...">` toggled via JS (`el.hidden = n === 0`). The `.pill { display: inline-flex; ... }` author rule always beats the browser's built-in `[hidden] { display: none }` UA rule (author origin wins over user-agent origin regardless of selector specificity or source order), so pills stayed visible showing "0" even when hidden was true. Fixed by adding `.pill[hidden] { display: none; }` right after the `.pill` rule. Found via manual Playwright screenshot verification (Task 7 of console-pilotage), not caught by the pytest asset guard test (which only checks file existence, no-innerHTML, no-emoji). Any future console component that sets a plain `display:` on an element also toggled by the `hidden` attribute needs the same `[hidden]` override, or must toggle a class instead of the attribute.
Evidence: Playwright screenshots before/after adding `.pill[hidden] { display: none; }`: before, Testeuses/Qualité pills showed \"0\" on the pilotage shell; after, they disappeared while Imports=1 stayed visible.
Verified by: Manual visual check via local uvicorn + Playwright screenshots (task7-shell-1280.png before/after) plus re-run of tests/api/test_admin_front_assets.py (still green, unaffected by the CSS-only fix).

# Cloudflare Access : bypass du webhook RevenueCat en place + tester le chemin public depuis le LAN avec curl --resolve

> Depuis le 2026 09 23, une application Cloudflare Access séparée « collega webhook revenuecat » self hosted, destinati…

Depuis le 2026-09-23, une application Cloudflare Access séparée « collega-webhook-revenuecat » (self-hosted, destination collegatest.matthislesur.com/v1/webhooks/revenuecat, une seule policy « bypass revenueCat » : action Bypass, Include Everyone) laisse passer le webhook RevenueCat (POST /v1/webhooks/revenuecat, billing_router monté sous /v1/webhooks dans main.py). L'application « collegatest » (policies email access + service token de l'app) protège toujours le reste du host : Cloudflare applique l'application au chemin le plus précis. La route se protège elle-même par le Bearer secret RevenueCat (billing.py). La durée de session et les fournisseurs d'identité de l'app de bypass sont sans effet (Bypass = aucune authentification). Pour tester le chemin public sans sortir du LAN (le DNS local court-circuite Cloudflare) : résoudre l'IP publique avec `dig +short @1.1.1.1 collegatest.matthislesur.com`, puis `/usr/bin/curl -X POST --resolve collegatest.matthislesur.com:443:<IP> https://collegatest.matthislesur.com/v1/webhooks/revenuecat`. Attendu : 422 FastAPI (corps manquant), c'est-à-dire que la requête atteint l'API ; 302 vers cloudflareaccess.com = encore bloqué. Contrôle : GET /health doit rester en 302. La règle met quelques dizaines de secondes à s'appliquer après sa création.

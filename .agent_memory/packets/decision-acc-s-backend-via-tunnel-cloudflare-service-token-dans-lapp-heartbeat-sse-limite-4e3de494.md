# Accès backend via tunnel Cloudflare : service token dans l'app + heartbeat SSE + limite 100 MB

> Pour que l'app mobile fonctionne hors LAN tunnel Cloudflare + Cloudflare Access , trois choses sont nécessaires. 1 L'…

Pour que l'app mobile fonctionne hors LAN (tunnel Cloudflare + Cloudflare Access), trois choses sont nécessaires. (1) L'app joint les headers CF-Access-Client-Id / CF-Access-Client-Secret (policy Access "Service Auth") à toutes les requêtes : helper cloudflareAccessHeaders() dans collega_app/lib/core/network/cloudflare_access.dart, câblé dans ApiClient._buildDio (les deux Dio, api + refresh), dans SseClient et dans BackgroundPartTransport (upload par morceaux). Les valeurs viennent de --dart-define=CF_ACCESS_CLIENT_ID / CF_ACCESS_CLIENT_SECRET (constantes cfAccessClientId / cfAccessClientSecret dans env.dart) ; vides → aucun header, ce qui reste correct sur le LAN. (2) Le stream SSE GET /v1/colleges/{id}/stream émet un commentaire `: keep-alive` toutes les _SSE_HEARTBEAT_INTERVAL (15 s) quand aucun événement n'est parti, car Cloudflare coupe une connexion silencieuse après ~100 s pendant la génération Claude ; _SSE_POLL_INTERVAL (1.5 s) est aussi une constante module pour les tests (tests/api/test_colleges_stream.py). Le parser SseClient Dart ignore les lignes ne commençant pas par `data:`. (3) Cloudflare (plan Free/Pro) rejette tout body > 100 MB en 413 avant le NAS : résolu par l'upload par morceaux (story 7.11) : parts de 25 MB (PART_SIZE, app/services/upload/chunked_upload.py), plafond 500 MB (MAX_UPLOAD_SIZE). Le webhook RevenueCat POST /v1/webhooks/revenuecat (billing_router monté sous /v1/webhooks dans main.py) arrive aussi par le tunnel et ne peut pas porter de service token : il faut une policy Access Bypass scoped sur ce path (l'endpoint vérifie déjà son propre Bearer secret).
Evidence: tests/api/test_colleges_stream.py vert (1 passed) ; suite tests/api : 16 échecs tous préexistants (Redis local absent, /register 403 by design, APNs) ; flutter test test/core/network/cloudflare_access_test.dart 2 passed ; flutter analyze clean ; curl --resolve sur l'IP Cloudflare → 302 cloudflareaccess.com sur toutes les routes.
Verified by: pytest + flutter test + flutter analyze, session 2026-09-20 ; Audit mémoire 2026-09-23 contre main 560e503 (lecture du code + tests ciblés verts)

# Prod collegatest : 2 chemins réseau, le chemin public est bloqué par Cloudflare Access

> Le backend prod backendBaseUrl dans collega app/lib/env.dart = collegatest.matthislesur.com est joignable par deux ch…

Le backend prod (backendBaseUrl dans collega_app/lib/env.dart = collegatest.matthislesur.com) est joignable par deux chemins très différents. (1) Depuis le LAN maison / tailnet : le résolveur DNS local override le hostname vers le NAS → Nginx Proxy Manager (proxy host n°53) → container collega-api-1:8000. Ce chemin fonctionne (GET /health 200, POST /v1/auth/login 401 attendu). (2) Depuis le DNS public : le hostname pointe vers Cloudflare (tunnel cloudflared) et TOUT le host est derrière Cloudflare Access → chaque route (/health, /v1/auth/login, /v1/colleges, /admin, /tester/) répond 302 vers cloudflareaccess.com/cdn-cgi/access/login. L'app mobile ne peut donc pas fonctionner hors LAN (4G, iCloud Private Relay qui résout via DNS public) si elle est compilée sans --dart-define=CF_ACCESS_CLIENT_ID / CF_ACCESS_CLIENT_SECRET (service token, voir cloudflare_access.dart et le packet « Accès backend via tunnel Cloudflare ») : les uploads « ne font rien », et comme chaque requête reçoit un 302 et jamais un 401, le refresh n'est pas déclenché et l'app reste « connectée » sur son cache drift offline-first (collèges qui paraissent vides). Pour diagnostiquer : `docker logs collega-api-1` et le log NPM `data/logs/proxy-host-53_access.log` sur le NAS — si une requête app n'y apparaît pas, elle n'a jamais atteint le backend.
Evidence: Probes curl 2026-09-20 : via DNS local → 200/401 et lignes visibles dans docker logs collega-api-1 + NPM proxy-host-53_access.log ; via --resolve sur l'IP Cloudflare publique → 302 vers cloudflareaccess.com sur toutes les routes. Logs API prod : zéro requête /v1 depuis 5 semaines.
Verified by: curl + ssh nas docker logs, session du 2026-09-20 ; Audit mémoire 2026-09-23 contre main 560e503 (lecture du code + tests ciblés verts)

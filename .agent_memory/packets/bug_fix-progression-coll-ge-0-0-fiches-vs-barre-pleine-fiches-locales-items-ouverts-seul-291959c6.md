# Progression collège « 0 % · 0 fiches » vs barre pleine : fiches locales = items ouverts seulement + collegeDetailProvider figé

> Repro iPhone 2026 09 21 CANCERO 177 fiches : Home/Collèges montraient une barre de progression pleine sans gris alors…

Repro iPhone 2026-09-21 (CANCERO 177 fiches) : Home/Collèges montraient une barre de progression pleine (sans gris) alors que le détail affichait « 0 % maîtrisé · 0 fiches ». Deux causes. (1) Les flashCards ne sont écrites en local (Drift) que par ItemDetailNotifier.syncCardsToDrift, c'est-à-dire à l'ouverture d'un item — l'import n'écrit aucune fiche. Le tile (collegeDrillStatsProvider) et le détail calculaient le « non vu » à partir des fiches cachées : après un drill sur un seul item, toutes les fiches locales étaient drillées → barre pleine. Fix : DrillStats.withTotal(serverTotal) déduit notSeen = total serveur (card_count_a/b/c de UserCollegeStatus ou d'ItemModel) − fiches drillées. (2) collegeDetailProvider est un AsyncNotifierProvider.family sans autoDispose, calculait les stats de drill une seule fois dans build() et n'était jamais invalidé → instantané figé jusqu'au redémarrage. Fix : collegeDrillStatsByItemProvider (StreamProvider.family sur flashCards.watch(), même pattern que le tile), combiné dans l'écran ; le calcul de drill a été retiré du notifier, du repository (getDrillStatsByItem) et d'ItemModel. Règle à retenir : toute stat de drill affichée doit venir d'un StreamProvider Drift (vivant) et son total de référence du serveur, jamais du cache local.
Evidence: Captures iPhone (barre pleine sur tiles, 0 fiches en détail) ; lecture du code : seule écriture de flashCards = syncCardsToDrift dans ItemDetailNotifier ; aucun ref.invalidate(collegeDetailProvider) dans lib/. Tests : drill_stats_test (withTotal), college_progress_tile_test (segment 162 gris), college_drill_stats_by_item_test (stream ré-émet après update drillLevel), college_detail_screen_test (« 40% maîtrisé · 5 fiches »).

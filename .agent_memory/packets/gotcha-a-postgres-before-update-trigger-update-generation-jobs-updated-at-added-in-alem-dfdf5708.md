# A Postgres BEFORE UPDATE trigger `update_generation_jobs_updated_at` (added in alembic mig

> A Postgres BEFORE UPDATE trigger update generation jobs updated at added in alembic migration 003 review fixes.py, fu…

A Postgres BEFORE UPDATE trigger `update_generation_jobs_updated_at` (added in alembic migration 003_review_fixes.py, function `update_updated_at_column()`) forces `generation_jobs.updated_at` to `now()` on every UPDATE of that row — it overrides any explicit value passed via an ORM attribute assignment AND via an explicit Core/ORM `update(GenerationJob).values(updated_at=...)` statement. Tests that need to antedate a job's `updated_at` (e.g. to simulate a stalled/old-failed job for the console de pilotage's watch_jobs/failed_imports_7d logic in app/services/admin_pilot.py) must temporarily disable the trigger: `ALTER TABLE generation_jobs DISABLE TRIGGER update_generation_jobs_updated_at`, run the UPDATE, then `ALTER TABLE generation_jobs ENABLE TRIGGER update_generation_jobs_updated_at`, all before commit. Verified empirically in tests/api/test_admin_pilot_pg.py::test_imports_en_echec_et_bloques — without disabling the trigger, the antedated value silently reverts to the current timestamp and the failed-imports-in-window filtering test fails.
Evidence: Debug test with raw UPDATE via SQLAlchemy Core/ORM statement still showed updated_at reverted to now() on read-back; disabling the trigger around the same UPDATE made the antedated value persist as expected.
Verified by: .venv/bin/python -m pytest tests/api/test_admin_pilot_pg.py -q (8 passed) after applying the DISABLE/ENABLE TRIGGER workaround

## Trigger

`ALTER TABLE generation_jobs DISABLE TRIGGER update_generation_jobs_updated_at`, run the UPDATE, then `ALTER TABLE generation_jobs ENABLE TRIGGER update_generation_jobs_updated_at`, all before commit. Verified empirically in tests/api/test_admin_pilot_pg.py::test_imports_en_echec_et_bloques — without disabling the trigger, the antedated value silently reverts to the current timestamp and the failed-imports-in-window filtering test fails.

## Verification

Debug test with raw UPDATE via SQLAlchemy Core/ORM statement still showed updated_at reverted to now() on read-back; disabling the trigger around the same UPDATE made the antedated value persist as expected.

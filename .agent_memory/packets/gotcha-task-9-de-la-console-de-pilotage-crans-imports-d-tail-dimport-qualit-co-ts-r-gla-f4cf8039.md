# Task 9 de la console de pilotage (écrans Imports, détail d'import, Qualité, Coûts, Réglage

> Task 9 de la console de pilotage écrans Imports, détail d'import, Qualité, Coûts, Réglages a révélé un piège dans le …

Task 9 de la console de pilotage (écrans Imports, détail d'import, Qualité, Coûts, Réglages) a révélé un piège dans le pattern vanilla-JS de la console admin (`app/static/admin/js/views/*.js`) : `Element.replaceChildren(...)` et `Element.append(...)` sont natifs et NE filtrent PAS les enfants `null`/`undefined` comme le fait `h()` (qui les élimine via `children.flat()` + filtre) — un argument `null` passé directement à `replaceChildren`/`append` est coercé en texte et affiche littéralement le mot « null » à l'écran. Le brief de task 9 pour `views/import.js` contenait ce bug verbatim (`content.replaceChildren(A, cond ? h(...) : null, B, C, segmentation(d))` où `segmentation(d)` retourne `null` quand `d.segmentation` est absent, ce qui est le cas courant pour un import en cours ou antérieur au chantier 4). Corrigé en empaquetant tous les enfants dans un tableau et en appliquant `.filter(Boolean)` avant de spreader dans `replaceChildren`. Vérifié par capture Playwright avant/après (le mot « null » apparaissait deux fois sur l'écran détail d'import). Règle pour la suite : toute vue qui construit sa liste d'enfants avec des conditions ternaires renvoyant `null` doit soit passer par `h()` (qui filtre), soit filtrer explicitement (`.filter(Boolean)`) avant d'appeler une méthode DOM native comme `replaceChildren`/`append`/`before`/`after`.

Deuxième point utile pour la vérification manuelle des futures tâches console : une capture Playwright `fullPage: true` d'un écran avec un header `position: sticky` (le `.topbar` mobile, actif sous 760px) peut faire apparaître ce header dupliqué/flottant au milieu de la page — c'est un artefact du stitching de capture plein-page de Chromium sur les éléments sticky, pas un bug réel (confirmé : un seul `.topbar` existe dans le DOM, et une capture `fullPage: false` du même écran est propre). Ne pas « corriger » ce genre d'artefact dans le CSS ; le signaler comme non-reproductible en usage normal (scroll réel) et, si besoin d'une preuve visuelle propre sur un écran long à 390 px, préférer plusieurs captures `fullPage: false` après scroll plutôt qu'une capture plein-page unique.
Evidence: Capture task9-import-detail-running-1280.png (avant fix) montrait « null » sous les KPI et en bas de page ; task9-import-detail-running-1280.png (après fix, même fichier régénéré) n'en montre plus. Repro isolée confirmant l'artefact sticky : page.locator('.topbar').count() === 1 alors que la capture fullPage montrait 2 occurrences visuelles.
Verified by: Capture Playwright avant/après + inspection DOM (count des .topbar)
